# Prior art worth taking (surveyed 2026-11-25)

The owner asked for a broad sweep — not "who else parses tcl", but general tools whose
code may help a hand-written, two-reader parser over a 45-language corpus. Everything
below was checked against the GitHub API (stars, licence, description) and, where it
matters, the files were listed to confirm the language coverage exists.

Ranked by what it buys us per hour of work.

## 1. Pygments / Chroma / Rouge — lexer state machines for the shell family

| repo | stars | licence | what it is |
|---|---:|---|---|
| `pygments/pygments` | 2,227 | BSD-2-Clause | generic syntax highlighter, 500+ lexers |
| `alecthomas/chroma` | 5,088 | MIT-style (NOASSERTION) | pure-Go port of Pygments |
| `rouge-ruby/rouge` | 3,457 | MIT-style | Pygments-compatible Ruby port |

Pygments ships exactly the lexers our losses cluster in: `pygments/lexers/php.py`,
`scripting.py`, `shell.py` (verified by listing the repo). These are hand-written state
machines for heredocs/here-strings, `$( … )` nesting, line continuations, raw strings and
nested interpolation — which is precisely the ground our two largest classes stand on
(`55 DifferentialMissingFact`, `15 MissingStatementTerminator`).

**Take:** the state transitions, not the code. For each language we are weak in, port the
minimal set: string delimiters and their escapes, heredoc markers, continuation rules,
comment nesting. Land them as reader rules with a fixture per transition — that is what
turns a class from "many files" to "one shape".

**Where:** `src/deep_facts/mod.rs` (per-language augmenters), `src/lexers/*`.

## 2. rust-analyzer — recovery instead of fallback

`rust-lang/rust-analyzer` (17,015★, Apache-2.0). Its parser never falls back: it consumes
tokens until a recovery point and records an error, so the tree still exists and the
construct keeps its shape. Our failure mode is the opposite — the guard rejects the whole
file when the two readers disagree.

**Take:** the recovery-set idea, one set per statement kind (what may legally follow a
declaration, an expression, a closing brace). A guard that recovers at the next statement
boundary converts one lost file into one lost construct, and the differential counter stops
attributing a whole file to one disagreement.

**Where:** the comparison guard in `src/pipeline.rs` and the CST driver.

## 3. tree-sitter grammars — the expected node shape, per language

`tree-sitter/tree-sitter` (27,571★, MIT). For every language we support there is a grammar
whose `node-types.json` states what a construct is made of. That is a free oracle for
"did our CST record the right shape", and a ready-made list of constructs to write fixtures
for, without reading another language's docs.

**Take:** node-type lists per language, used to generate fixtures and to name FRCE classes
at the construct level rather than at the file level.

## 4. tokei / scc — a second opinion on the LOC metric

`XAMPPRocky/tokei` (15,115★), `boyter/scc` (8,893★, MIT). Both count code, comment and
blank lines separately and support the languages we measure.

**Take:** cross-check `tools/loc_weighted.py` against `scc --by-file --format json` on two
languages. If our "non-blank lines" includes comment-only files, our LOC% is inflated and
we are chasing losses a reader cannot fix. The owner's new gate is LOC-based, so the metric
itself has to be right.

## 5. github-linguist — is the corpus classified correctly

`github-linguist/linguist` (13,805★, MIT). Extension and content heuristics per language.

**Take:** one pass over the corpus to confirm every file we count belongs to the language we
count it under. A misclassified file is a guaranteed fallback (no reader) that pollutes a
percentage for a language that is actually clean.

## 6. Grammar-based fuzzing — new classes on demand

Grammar-driven generators (e.g. `renatahodovan/grammarinator`) build inputs from a grammar
rather than mutating bytes. Fed a tree-sitter grammar, they produce the odd-but-legal
constructs a corpus rarely contains.

**Take:** per language, generate a small set, run both readers, and let FRCE classify the
disagreements. This is how we find class 56+ rather than waiting for a corpus file to
surface it.

## Adoption order

1. `scc` cross-check of the LOC metric (an hour, protects the gate itself).
2. linguist pass over the corpus (an hour, removes phantom languages).
3. Port state machines for the two worst shell-family languages from Chroma/Pygments.
4. Recovery sets from rust-analyzer for the differential classes the guard still rejects.
5. Grammar-derived fixtures and fuzz inputs to keep FRCE's class table growing.

Nothing here is copied wholesale: licences are permissive (BSD/MIT/Apache), and what we
take is a rule or an idea, re-expressed in our own reader.
